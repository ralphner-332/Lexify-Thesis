<objective>
Build the backend Semantic AI Evaluation Engine, Assessment Session Management, Dual-Layer Snapshot Security, and Immutable Evaluation Persistence for Phase 2:
1. Prisma schema models for `AssessmentSession` (with FULL authoritative `questionsSnapshot`), `StudentAnswerDraft`, and `Evaluation` (with `questionSnapshot`, `modelConfigSnapshot`, and `rubricSnapshot`).
2. Server-side session & draft management with server-enforced DTO sanitization (Students receive scenario only; FULL evaluation context is safely stored in database for AI evaluation).
3. Mandatory answer validation requiring non-empty answers for all predetermined questions before final submission.
4. Modular LLM Provider architecture with `ILLMProvider` interface, Google Gemini adapter, and fail-safe provider factory (no silent provider switching or fake score generation in research mode).
5. Semantic AI evaluation engine with Zod schema validation, dynamic rubric-derived maxScore calculation, strict anti-hallucination prompting, and demo simulation tagging (`isDemo: true`).
6. AI evaluation grounding strictly derived from `AssessmentSession.questionsSnapshot` (immune to subsequent `Question` table edits).
7. Absolute immutability: zero update/delete routes for Evaluation, and submitted sessions permanently locked.
8. Automated behavioral verification test suite.

Purpose: Deliver a rigorous, reproducible, and secure AI evaluation backend grounded in Philippine Criminal Law I reference materials.
Output: Working Express REST endpoints for student assessment sessions, submission processing, and AI evaluation retrieval.
</objective>

       - `id`: String @id @default(uuid())
       - `studentId`: String
       - `status`: String @default("IN_PROGRESS") // "IN_PROGRESS" | "SUBMITTED"
       - `questionsSnapshot`: String @default("[]") // Authoritative JSON snapshot of FULL question objects (code, title, scenario, modelAnswer, statutoryElements, relevantProvisions, conceptVariations, orderIndex) when session began
       - `startedAt`: DateTime @default(now())
       - `submittedAt`: DateTime?

       - `createdAt`: DateTime @default(now())

    2. `StudentAnswerDraft`:
       - `id`: String @id @default(uuid())
       - `sessionId`: String
       - `questionId`: String
       - `answerText`: String
       - `updatedAt`: DateTime @updatedAt
       - Unique constraint on `(sessionId, questionId)`.
    3. `Evaluation`:
       - `id`: String @id @default(uuid())
       - `sessionId`: String
       - `studentId`: String
       - `questionId`: String
       - `agentVersionId`: String // e.g. "V1"
       - `questionSnapshot`: String // Immutable JSON snapshot copied directly from AssessmentSession.questionsSnapshot
       - `modelConfigSnapshot`: String // Immutable JSON snapshot of LLM settings (provider, modelId, temperature, topP, maxTokens)
       - `rubricSnapshot`: String // Immutable JSON snapshot of rubric criteria and weights
       - `studentAnswer`: String
       - `numericalScore`: Float
       - `maxScore`: Float // Dynamically derived from sum of criteria maxPoints
       - `scoringBasis`: String
       - `criterionScores`: String // JSON array: [{ criterionName, score, maxPoints, reasoning }]
       - `strengths`: String // JSON array of strings
       - `missingElements`: String // JSON array of strings
       - `areasForImprovement`: String // JSON array of strings
       - `confidenceScore`: Float @default(1.0)
       - `reviewFlags`: String @default("[]") // JSON array of review flags
       - `isDemo`: Boolean @default(true)
       - `createdAt`: DateTime @default(now())
       - Strictly NO `updatedAt` field on Evaluation — append-only!
    Push schema to SQLite database via `npx prisma db push`.

    - `toStudentSessionDTO(session, drafts)`: Parses the FULL `session.questionsSnapshot` and strictly SANITIZES it for student response. Returns ONLY `{ id, status, startedAt, submittedAt, questions: [{ id, code, title, scenario, orderIndex, draftAnswer }] }`. Explicitly strips `modelAnswer`, `statutoryElements`, `relevantProvisions`, and `conceptVariations`.
    Implement `src/services/assessment-session.service.ts`:
    - `getOrCreateActiveSession(studentId, isDemo)`:
      - Looks for existing `IN_PROGRESS` session.
      - If none exists, fetches all active Questions, captures FULL `questionsSnapshot` (storing complete question configuration and sequence), and creates new `AssessmentSession`.
      - Returns sanitized session view via `toStudentSessionDTO`.
    - `saveAnswerDraft(sessionId, studentId, questionId, answerText)`:
      - Validates session belongs to `studentId` and is `IN_PROGRESS`. If `SUBMITTED`, throws error `400 Bad Request: Cannot modify draft for submitted session`.
      - Upserts `StudentAnswerDraft` record.
    - `getSessionReview(sessionId, studentId)`:
      - Retrieves questions from session's `questionsSnapshot`, maps each question to draft answer, and checks `isAnswered` (true if answerText is non-empty).
      - Returns sanitized question status array and `allAnswered` boolean flag.
    - `submitSession(sessionId, studentId)`:
      - Validates session is `IN_PROGRESS`.
      - Checks that EVERY question in `questionsSnapshot` has a non-empty answer draft. If any question is missing or blank, throws `400 Bad Request: All questions are required before final submission`.
      - Updates session `status: "SUBMITTED"`, `submittedAt: new Date()`.
      - Immediately triggers evaluation service for each question answer using the FULL `questionsSnapshot` as source.
      - Logs audit entry `SUBMIT_ASSESSMENT_SESSION`.
    Implement `assessment-session.controller.ts` & `assessment-session.routes.ts` with Student role authorization.

      - `scoringBasis`: string
      - `criterionScores`: array of `{ criterionName, score, maxPoints, reasoning }`

      - `reviewFlags`: string[]

      - Injects system instructions, scenario, reference answer, statutory elements, provisions, concept variations, and rubric criteria.

      - In research mode (`isDemo: false`): Calls provider. If provider fails or API key is missing, throws error (fail safe, no fabricated score).
      - In demo mode (`isDemo: true`): Calls provider if available; if offline, executes structured demo simulation clearly marked with review flag `DEMO_SIMULATION`.
      - Validates output with `EvaluationOutputSchema` and verifies `maxScore` equals the sum of rubric criteria `maxPoints`.
